# MITRE ATT&CK Mapping and Coverage

`sigma_attack` is an offline mapping and reporting layer for the standard
MITRE ATT&CK metadata already present in Sigma rules. It does not add custom
fields to rule YAML and does not modify rule objects, so rules remain valid for
pySigma, Sigma CLI, and existing backends.

## Supported tags

The mapper interprets tags in the `attack` namespace:

| Tag | Meaning |
| --- | --- |
| `attack.t1059` | Technique `T1059` |
| `attack.t1059.001` | Subtechnique `T1059.001` |
| `attack.execution` | Tactic `execution` |
| `attack.s0002` | Software |
| `attack.g0069` | Intrusion set |
| `attack.ds0005` | Data source |
| `attack.m1040` | Mitigation |
| `attack.c0001` | Campaign |

Technique IDs are normalized to uppercase. Tactic names are normalized to the
lowercase, hyphenated ATT&CK short names. The legacy `defense-evasion` spelling
is accepted as an alias for `stealth`; `privilege_escalation` and
`command_and_control` are normalized automatically.

Tags are accepted as strings or as pySigma `SigmaRuleTag` objects. Unknown
attack-namespace tags and unknown technique IDs are preserved in the mapping
and reported by `validate`, so a newer ATT&CK catalog does not silently discard
metadata.

## Per-rule mapping

```bash
python -m sigma_attack map rules/ --format json -o mappings.json
python -m sigma_attack map rules/ --format csv -o mappings.csv
```

Each mapping contains:

- `techniques`: sorted canonical technique IDs.
- `tactics`: explicit tactic tags plus tactics derived from each technique.
- `explicit_tactics`: only tactics directly tagged on the rule.
- `software`, `groups`, `data_sources`, `mitigations`, `campaigns`.
- `unknown_techniques` and `unknown_attack_tags`.
- `mapped`: whether the rule has at least one technique or tactic.

Example Python usage:

```python
from sigma_attack import build_coverage, map_rule, map_rules

mapping = map_rule("rules/windows/process_creation/example.yml")
print(mapping.techniques, mapping.tactics)

report = build_coverage(map_rules("rules/"))
print(report.summary())
```

`map_rule` also accepts a `yaml.safe_load` mapping or a pySigma `SigmaRule`:

```python
from sigma.rule import SigmaRule
from sigma_attack import map_rule

with open("rule.yml", encoding="utf-8") as handle:
    rule = SigmaRule.from_yaml(handle.read())
mapping = map_rule(rule)
```

## Coverage report

```bash
python -m sigma_attack coverage rules/ --format markdown -o coverage.md
python -m sigma_attack coverage rules/ --format json -o coverage.json
python -m sigma_attack coverage rules/ --fail-under 80
```

The JSON report contains:

- Rule coverage: rules with a technique, tactic-only rules, and rules with no
  ATT&CK mapping.
- Coverage by technique: rule count, tactic memberships, and per-rule
  references.
- Coverage by tactic: catalog technique denominator, covered and uncovered
  technique IDs, and rule count.
- Unknown technique/tag details and the full list of rules without a technique.

The denominator comes from the bundled enterprise ATT&CK catalog. Coverage is
reported per tactic and globally; a technique that belongs to multiple tactics
is counted in each tactic. Subtechniques are counted separately by default.

## ATT&CK Navigator layer

```bash
python -m sigma_attack navigator rules/ -o attack-layer.json
python -m sigma_attack navigator rules/ -S -o attack-layer-no-subtechniques.json
```

The layer uses the same fields as `sigma analyze attack count`: `techniqueID`,
`tactic`, `score`, `color`, `comment`, `enabled`, `metadata`, `links`, and
`showSubtechniques`. The score is the number of matching rules.
`-S`/`--no-subtechniques` rolls subtechnique scores up to the parent technique.

## Validation

```bash
python -m sigma_attack validate rules/
python -m sigma_attack validate rules/ --fail-on-unmapped
```

Validation fails on unknown technique IDs or unknown `attack.*` tags. The
optional `--fail-on-unmapped` flag also fails when a rule has no ATT&CK
technique.

## Converter compatibility

The implementation is designed to interoperate with the existing Sigma
ecosystem:

- Only the standard `tags` field is read.
- pySigma `SigmaRule`/`SigmaRuleTag` objects are accepted directly.
- Rule objects and YAML files are never mutated.
- Navigator output follows the schema generated by Sigma CLI.
- `python tests/test_attack_mapping.py` includes pySigma conversion checks and
  skips them cleanly when pySigma is not installed.

The test suite also contains a manually reviewed fixture of 50 rules spanning
Windows, Linux, macOS, cloud, network, identity, and application log sources.
The automatic mapping must match the reviewed technique and tactic labels for
all 50 rules exactly.

## ATT&CK catalog

The bundled catalog is generated from the official enterprise ATT&CK STIX
bundle. It contains the ATT&CK version, tactic IDs and names, technique names,
tactic memberships, and parent technique IDs. `AttackCatalog.from_stix()` can
build a replacement catalog from an official STIX file:

```python
from sigma_attack import AttackCatalog

catalog = AttackCatalog.from_stix("enterprise-attack.json")
print(catalog.version, len(catalog.techniques))
```

Pass `--catalog FILE` to any CLI command to use a generated catalog JSON.
